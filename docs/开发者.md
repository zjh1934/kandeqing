## 工程结构

标准 Gradle 结构，根目录 `settings.gradle`，代码在 `app/` 模块。**没有提交 gradle wrapper**（一直用 AIDE / Actions 构建）。

| 文件 | 职责 |
|---|---|
| `ComboService.java` | 唯一服务：手势分发 + 状态机 + 取字覆盖层 + 保活通知 |
| `BallController.java` | 手势判定（拖动 / 按住放大 / 轻点）、放大时的坐标补偿 |
| `BallView.java` | 球的绘制：柔边环 / 实心球 / 环加两竖 / 加载转圈 |
| `ZoomController.java` | 系统放大控制（倍率、中心点、屏幕↔内容坐标换算） |
| `TextGrabber.java` | 抓字：多窗口取根 → 收集 → 阅读顺序 → 触点定位 → 句起点 |
| `TextLayout.java` | 纯排版逻辑（阅读顺序 / 断句），无 Android 依赖，可单测 |
| `TtsManager.java` | TTS 引擎与音色、长文本切段、按会话号丢弃过期回调 |
| `Haptics.java` | 触觉反馈，不同状态不同节奏 |
| `Prefs.java` | 设置读写（唯一出入口） |
| `MainActivity.java` | 四个 Tab 的界面（声音 / 调节 / 悬浮球 / 更多） |

纯 Java，无第三方运行时依赖。`compileSdkVersion 30` / `minSdkVersion 24`（Android 7.0）/ `targetSdkVersion 29`。

## 抓字链路（3.9.7 起，以官方契约为准）

**只走 `AccessibilityNodeInfo` 树。OCR / 截图 / MediaProjection / 像素识别整条排除。**
依据来自 Android 官方 API 参考与 AOSP 源码原文。

- **放大态显式拒绝抓字**：官方源码写明 `getBoundsInScreen` 与逐字位置 `RectF` 都会被放大倍率缩放、按视口偏移调整；不受影响的 `IN_WINDOW` key 是 API 36，本工程 `compileSdk 30` 够不着。所以只在未放大态抓字。
- **预算只截收录、不截遍历**：`MAX_SEG` 400 → 2000，且不再是 `walk()` 入口的访问闸。旧版一到 400 就整棵子树不再访问，500 段长列表点第 450 段必然抓不到。AOSP 预取上限只约束一次请求附带的批次，不是应用层遍历预算。
- **文本按官方语义分角色**：`getText()` / `getContentDescription()` 才进连续正文串；`getHintText` / `getTooltipText` / `getStateDescription` / `getPaneTitle` 命中时照读，但不拼进正文（不会把「请输入手机号」念成文章）。
- **逐字位置按契约取**：先查 `getAvailableExtraData()`，只对命中段请求一次，长度夹在 20000；`refreshWithExtraData` 返回 false 或 `RectF` 全 null 一律降级按行估算，**任何失败路径都不返回 0**（0 = 从篇头读）。
- **可见性重算不重扫树**：`isVisibleToUser()` 在 API 16–29 放大时可能误报 false，被软过滤的段收进纯数据快照，关过滤时合并重算，不再对同一根二次 `walk()`。
- **兜底跨窗口全局比较**：`grabAt` 不再「第一个命中窗口就 break」。
- **句读回扫设上限**：160 字内找不到标点就从命中字附近读，不退到段首。

逐字位置在遍历阶段一次算好存进段数据，后续全是纯计算，快照之后不再碰节点对象。

其它要点：

- `getRootInActiveWindow()` 只在窗口内容变化时才取得到数据，经常返回 null，也拿不到弹窗 / 输入法 / 分屏另一半 → 走 `getWindows()` 按 layer 扫。
- 阅读顺序不能只按 `(top, left)` 排，多列布局会读乱序 → 先把垂直重叠过半的归成一行，行内再按 left 排。
- `AccessibilityNodeInfo` 是有限系统资源，漏 `recycle()` 会让后续 `getChild()` 抛异常，表现为「读一会儿就抓不到字了」。
- Android 只有一个 `TYPE_SYSTEM` 同时代表状态栏和导航栏，没有 `TYPE_STATUS_BAR` / `TYPE_NAVIGATION_BAR`。

## 放大的坐标

系统放大映射（内容坐标 C → 屏幕位置 P，放大中心 K，倍率 s）：

```
P = S/2 + s × (C − K)
```

要的是「手指移到哪，就看到那个位置的放大内容」——手指是**不动点**：

```
K = fx − (fx − S/2) / s
```

推论：在不动点处，内容坐标 = 屏幕坐标，所以球窗口位置是 `fx − 球宽/2`。

`S` 必须是与 `getRawX/Y()` 同源的物理屏幕尺寸。用不含虚拟导航栏的 `getMetrics()` 会破坏不动点，球恒定偏移、靠底部还会被倍率放大。

**不能写成 `K = K0 − ΔF/s`**，那是「手指抓着内容不动」，画面会相对手指静止，看着像不会动。

## 朗读的两个坑

- **单次上限 4000 字**：`TextToSpeech.getMaxSpeechInputLength()`，超了 `speak()` 直接返回 ERROR。长文章必须切段排队。
- **打断会产生假回调**：新朗读 flush 掉上一句时，被 flush 那句也会回调 `onDone`。每段带会话号，回调时比对，过期的丢掉。

## 自检

开发机没有 JDK / Android SDK 时用 Python 镜像兜底：

```bash
python3 verify_all.py     # 跑三遍，全绿
```

| 脚本 | 检查什么 |
|---|---|
| `verify_structure.py` | 括号配对、跨文件符号解析、import 缺失 |
| `verify_textlayout.py` | 阅读顺序、断句逻辑的镜像 |
| `verify_grabber.py` | 抓字全流程镜像（收集 / 排序 / 拼装 / 回收） |
| `verify_textcompare.py` | 续读去重：只比相等，不比包含 |
| `verify_speak.py` | 长文本切段：不吞字、不重字、每段不超上限 |

> ⚠️ 这些脚本**只验逻辑，不验 API**。曾在自检全绿的情况下写出不存在的系统常量，真编译一次才发现。**有 JDK 就必须真跑一次 javac。**

## 构建

**GitHub Actions（当前路径）**：push 到 `main` 自动用固定签名密钥出包、回传 `apk/`、发布 Release。不需要本地装 Android SDK。

**AIDE**：用 AIDE 打开工程根目录（含 `build.gradle` / `settings.gradle` 那一层），直接 Build。

**Android Studio**：根目录执行 `gradle wrapper`，在根 `build.gradle` 补 AGP classpath，再 `Build → Build APK(s)`。

**命令行（aapt2 + javac + d8 + apksigner）**：见 `build_apk.sh`。要在纯英文路径下编译 —— aapt2 打不开含中文的目录。

## 已知限制

- 读不到图片里的字、Canvas 自绘文字、多数游戏界面 —— 只走无障碍树，不做 OCR
- 依赖 App 向无障碍暴露文字
- 放大是像素放大，字会毛边，不会重新排版
- 部分国产 ROM 省电策略会自动关闭无障碍服务
- 未上架应用商店；从 3.7 起签名固定，可覆盖安装
- `targetSdkVersion 29` 为 AIDE 构建保留；上架商店需 33+ 并补 `foregroundServiceType`、`POST_NOTIFICATIONS`
