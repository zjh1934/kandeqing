# 看得清 · 主页设计说明

> 这份文档回答「为什么这么排」，不重复 `index.html` 里的文案。
> 改页面之前先读它；改完页面要同步更新本文和 `verify_pages.py` 的断言。
> 设计决策同样写进了 AOCI Code 卷里 `docs/index.html` 的 S 字段。

---

## 一、旧版为什么"拉垮"

按顺序盘点，都是可复现的问题，不是审美分歧：

| 问题 | 后果 |
|---|---|
| 深灰底 + 一堆小 pill + 抽象圆环大图 | 首屏看不到产品长什么样，访客要先读三行小字才知道这是什么 |
| 首屏塞了「两个动作」「状态说明」「隐私」「订阅/下载两类链接」 | 技术细节挤占主视觉，普通人 5 秒内答不出"我能立刻干什么" |
| 订阅源、直链、CDN 缓存、SHA256 这些写成正文大段 | 那是给下载器看的，不该是主页的主叙事 |
| 4 个 section 挂在 `</footer>` 之后 | 页脚下又冒出内容，页面像没写完 |
| 同一页同时展示 3.9.23 明朗七色和更早的低饱和预览 | 自相矛盾，访客不知道哪个是现在的样子 |
| 对比表里没有"复制朗读"列 | 明明做成两个球，卖点却没写进去 |

## 二、参考了谁，学到什么

不是抄样式，是抄**信息架构和决策依据**。

| 参考 | 学到的做法 | 用在本页 |
|---|---|---|
| **Vite** 官网 | 极浅底、超大两行主标题、一行副标题、一个实心主 CTA + 两个描边次 CTA；下方 2×3 卡片带小图标；留白极大 | 首屏字号节奏、按钮层级、三步卡片 |
| **shadcn/ui** 官网 | Hero 右侧直接放**真实产品形态**（表单 / 日历组件），不用抽象渐变装饰；几乎纯白、大黑体 | Hero 右侧改成手机 + 放大镜 + 两球的产品示意 SVG |
| **Excalidraw** 官网 | 一句话副标题、单一主 CTA、把可验证的数字（Star 数）做成顶部可信度信号 | 数字弹药库、单一主 CTA |
| **Designify · Open Source Project Website Design** | 主页要放：一句话描述、安装路径、活的可信度信号、贡献者入口、许可；README 和网站分工不同，别把 README 粘进模板 | 首屏三问、proof 数字条、页脚仓库/参与两列、README 重排 |
| **daily.dev · README as Landing Page** | Quickstart → Features → Docs → Community 的顺序；高信号 vs 低信号元素对照；标题要能独立读懂；**指令不能只放在图里** | 三步上手放在对比表之前，订阅/直链收进折叠区 |
| **AstroWind 落地页解剖** | 渐进披露：Hero 承诺 → 步骤 → 证据 → FAQ 消化异议 → 收尾 CTA 重复同一个按钮 | 折叠 FAQ、底部重复主 CTA |
| **华为云可访问性实践** | 语义化标签、`:focus-visible`、`prefers-reduced-motion`、`prefers-contrast`、正文 4.5:1、字号可缩放 | 见第四节 |

另外一条硬约束来自本项目自己：**预览图一律代码自绘，不用生图模型**。
所以 Hero 的手机示意图是内联 SVG，不是生成的图片，也不是真机截图。

## 三、信息架构（从上到下）

1. **Hero**：一句话价值主张（"字太小？按住放大。不想看？点一下，念给你听。"）
   + 一行受众 + 一个主 CTA（raw 固定直链）+ 一个次 CTA（跳到怎么用）
   + 版本 / 平台 / 零联网 / 许可的可信度行；右侧产品示意图 + 三动作图例。
2. **数字弹药库**：40 个历史版本 / 10 套自检 ×3 轮 / 0 项联网权限 / 74 个受管文件 / MIT。
   都是能从仓库数出来的事实，不是"轻量、高效、可扩展"这类虚词。
3. **三步上手**：三个动作各一张卡，编号 + 图标 + 一句说明 + 一行"结果 →"。
   下面一条 note 交代两个开关、Android 10+ 限制、诊断与日志。
4. **为什么不一样**：对比表（含"复制朗读"列）+ 一句"这是选的路，不是没修完"。
5. **3.9.23 看得见的改动**：三条要点 + 两张代码自绘预览 + 四种球形态的小图例。
   明确写"更早那套低饱和配色已被取代"，不再展示过时预览。
6. **隐私**：左文右 `AndroidManifest.xml` 片段，把"零 INTERNET"当成可核对的证据。
7. **给谁用 / 请换工具**：诚实写边界，比把功能吹满更让人放心。
8. **代码也是受管的 · AOCI**：一小节，链接到 `docs/aoci.md` 和本文。
9. **下载与更新**：主下载卡片 + 两个 `<details>` 折叠（下载器用的两类链接、常见问题）。
   技术细节不占主视觉，需要的人自己展开。
10. **收尾 CTA**：重复同一个主按钮；**footer 统一放在所有 section 之后**。

## 四、视觉与可访问性决策

- **浅色为主**：`#FBFAF7` 近白底 + `#12161C` 近黑字，正文 17px / 1.8。
  给低视力人群做的工具，主页自己必须高对比；`prefers-color-scheme: dark` 自动切深色，
  `prefers-contrast: more` 再加深文字与边框。
- **一个主色 + 一个强调色**：电蓝 `#1E6BFF`（和 App 的白球一致）、亮绿 `#00A86B`（和绿球一致），
  其余全是中性灰。卡片用 1px 细边框 + 极轻阴影，不用重投影、不用毛玻璃堆效果。
- **零外部依赖**：单文件 HTML，不引 Google Fonts、不引 CDN CSS、不加载 JS。
  系统字体栈、内联 SVG、相对路径的两张预览图。
  **访客网络再差，页面结构和文字也一定在** —— 这条是硬要求。
- **可访问性清单**：跳过导航链接、`:focus-visible` 三像素描边、语义化
  `header / nav / main / section / article / footer`、标题层级连续、
  SVG `role="img"` + `aria-label`、表格 `<caption>` + `scope`、图片 `alt` + `loading="lazy"`、
  按钮最小高度 56px、`prefers-reduced-motion` 关动效、移动端表格横向滚动、锚点 `scroll-margin-top`。
- **指令不只放在图里**：Hero SVG 有完整 `aria-label`，图例和三步卡片用文字把三个动作再说一遍。

## 五、怎么防止设计又退化

`verify_pages.py` 把设计约束也纳入了 `verify_all.py` 10 套三轮 + CI 构建前一步：

- 所有主 CTA 必须指向 raw 固定直链（不能退回会滞后一版的 jsDelivr 同名文件）；
- 最后一个 `<section` 必须在 `<footer` 之前，不得再出现页脚后悬挂内容；
- 不得出现已被取代的旧版本预览节与旧首屏措辞；
- **零外部依赖**：页面里不得出现 `<script`、`fonts.googleapis`、`cdn.tailwindcss`、
  `<link rel="stylesheet"` —— 防止有人为了"好看"引一堆外链，把弱网访客挡在门外；
- **可访问性基线**：`skip` 链接、`:focus-visible`、`prefers-reduced-motion`、
  `prefers-contrast`、`aria-label`、`loading="lazy"` 缺一即失败；
- **产品可视化**：Hero 必须有内联产品示意 SVG + 三动作图例；技术细节必须收进 `<details>`；
- 版本、订阅源、固定直链、AOCI、诊断与日志等口径由原有断言继续把关；
- 本文件必须存在并列出参考项目，改设计要同步改它；
- **数字条是活数据**：受管文件数对齐 `.aoci/baseline.json`、历史版本数对齐
  `docs/feed.atom` 的 `<entry>` 数、自检套数对齐 `verify_all.py` 的 SUITES、
  零联网权限对齐 `AndroidManifest.xml`、MIT 对齐 LICENSE，写死过期数字会被点名；
- 视觉自查：桌面 1440 / 平板 768 / 手机 390 / 窄屏 320，以及 200% 缩放等效的
  195 CSS px 视口，五个宽度都不出现横向溢出；桌面、手机、深色三种首屏人眼各看一遍。

改页面后固定动作：

```bash
python3 verify_pages.py
python3 tools/aoci_cognition.py --check   # 页面行数变了可能改 Code 卷的规模档
python3 tools/aoci_sync.py --refresh
python3 verify_all.py
```

绿色只证明结构与口径对齐，**不等于好看**。视觉改动仍要人眼在桌面和手机各看一遍。
